### 3. [항목 #5, #9] 라우터(Router) 설계 및 분기 실행 근거
**보완 내용:** '오전/오후'를 나누는 상세 로직을 설명합니다. (스크린샷은 직접 찍어서 첨부하셔야 합니다!)

*   **Router 조건표:**
    *   **Path A (오전):** 조건 `응답값`에 "오전" 포함 → Action: '오전용' 시트 저장 및 메일 발송
    *   **Path B (오후):** 조건 `응답값`에 "오후" 포함 → Action: '오후용' 시트 저장 및 메일 발송
*   **실행 로그 예시:** "2023-10-27 10:00:05 - Filter Passed (Morning Path) - Email Sent Successfully."

### 4. [항목 #8] 단계별 입출력 샘플 데이터
**보완 내용:** 데이터가 어떻게 변하는지 예시를 보여줍니다.

| 단계 | 데이터 예시 (Input/Output) |
| :--- | :--- |
| **Trigger (구글폼)** | `{"이름": "홍길동", "시간": "오전", "이메일": "test@mail.com"}` |
| **Filter/Router** | `Condition: 시간 == "오전" (True)` |
| **Action 1 (시트)** | `구글 시트 '오전' 탭에 "홍길동", "test@mail.com" 추가` |
| **Action 2 (메일)** | `수신: test@mail.com / 제목: [오전] 신청 완료 안내` |

### 5. [항목 #10] Trigger와 Action의 정의
**보완 내용:** 개념적 차이를 명확히 기술합니다.
> *   **Trigger (트리거):** 자동화 시나리오가 시작되는 '계기'입니다. (예: 새 설문 응답 발생)
> *   **Action (액션):** 트리거 발생 후 AI가 실제로 수행하는 '동작'입니다. (예: 이메일 발송, 시트 기록)

### 6. [항목 #12] 선정 근거와 비교 항목 매칭
**보완 내용:** 왜 이 도구를 선택했는지 비교 항목과 연결합니다.
> "복잡한 조건 분기(Router)가 필수적인 프로젝트 특성상, **비용 대비 실행 횟수가 많고 시각적 로직 설계가 자유로운 Make**를 주 도구로 선정하였습니다. 반면, 빠른 설정이 필요한 단순 업무에는 **접근성이 좋은 Zapier**가 유리함을 확인했습니다."

### 7. [항목 #13] 모니터링 및 재시도 전략
**보완 내용:** 에러 발생 시 대처 방안을 추가합니다.
*   **모니터링:** Make의 'Dashboard'를 통해 실시간 실행 성공/실패 여부 확인.
*   **재시도 전략:** 에러 발생 시 나에게 즉시 슬랙(Slack) 알림이 오도록 설정하고, 실패한 데이터는 'Incomplete Executions' 저장소에서 수동 재실행함.

### 8. [항목 #14] 모듈화 및 재사용 방안
**보완 내용:** 규모가 커질 때를 대비한 설계 아이디어입니다.
*   **방안:** 공통으로 사용하는 '이메일 발송' 부분은 별도의 **Webhook** 시나리오로 분리하여, 다른 설문 자동화에서도 호출하여 재사용할 수 있도록 설계함.

### 9. [항목 #15] 코딩 확장 아이디어 (노코드 한계 보완)
**보완 내용:** 노코드 툴만으로 부족한 점을 코드로 보완하는 방법입니다.
*   **한계:** 구글 시트 내에서 아주 복잡한 수학적 계산이나 데이터 가공은 노코드 툴에서 클릭만으로 구현하기 번거로움.
*   **확장 아이디어:** **Google Apps Script(GAS)**를 사용하여 시트 내 데이터를 1차 가공한 뒤, Make가 가공된 데이터를 가져가도록 설계하면 훨씬 효율적인 자동화가 가능함.
