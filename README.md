# codyssey1-3

# [최종 보고서] 노코드 도구(Make vs Zapier) 비교 및 업무 자동화 파이프라인 구축

## 1. 개요 및 도구 정의 (평가항목 #10 보완)
본 프로젝트는 구글 폼 응답에 따른 자동 안내 시스템을 구축하며, 노코드 도구의 핵심 개념을 다음과 같이 정의하고 시작합니다.
*   **Trigger (트리거):** 자동화 시나리오가 시작되는 '계기'입니다. (예: 새 설문 응답 발생)
*   **Action (액션):** 트리거 발생 후 시스템이 실제로 수행하는 '동작'입니다. (예: 이메일 발송, 시트 기록)

## 2. [프로젝트 1] 도구 비교 분석 (평가항목 #3, #11, #12 보완)

### 2.1 도구 선정 근거
가장 대중적인 **Make**와 **Zapier**를 비교 대상으로 선정했습니다. 
*   **Make:** 시각적 맵 구성이 가능하여 복잡한 로직 구현에 강점이 있고, 무료 플랜의 실행 횟수가 넉넉합니다.
*   **Zapier:** 직관적인 UI로 초보자 접근성이 높고 연동 가능한 앱이 가장 많습니다.

### 2.2 상세 비교표 (5개 항목)

| 비교 항목 | Make (구 Integromat) | Zapier |
| :--- | :--- | :--- |
| **사용 난이도** | 중 (드래그 앤 드롭 방식, 학습 필요) | 하 (단계별 가이드 제공, 매우 쉬움) |
| **가격 (무료플랜)** | 1,000 Ops/월 (넉넉함) | 100 Tasks/월 (매우 제한적) |
| **로직 복잡도** | 상 (다중 분기 및 Router 기능 강력) | 중 (단순 선형 구조 위주) |
| **실행 속도** | 빠름 (실시간에 가까운 처리) | 보통 (플랜에 따라 15분 간격 폴링) |
| **협업 및 운영** | 시나리오 공유 및 로그 확인이 상세함 | 권한 관리 및 팀 공유가 매우 직관적임 |

### 2.3 협업 및 운영 영향 분석
*   **Make:** 복잡한 워크플로우를 시각적으로 한눈에 볼 수 있어, 운영 중 에러 발생 지점을 찾기가 매우 유리합니다.
*   **Zapier:** 설정이 간편하여 팀 내 비개발자들도 쉽게 자동화 흐름을 수정하고 관리할 수 있어 협업 효율이 높습니다.

## 3. [프로젝트 2] 자동화 파이프라인 설계 (평가항목 #5, #7, #8, #9 보완)

### 3.1 시나리오 구조
*   **Trigger:** 구글 폼에 새로운 신청서 접수 (15분 간격 체크)
*   **Router (분기):** 신청 시간대(오전/오후)에 따른 경로 최적화
*   **Action 1:** 구글 스프레드시트 해당 시간대 탭에 데이터 기록
*   **Action 2:** 신청자에게 맞춤형 안내 이메일 발송

### 3.2 라우터(Router) 설계 및 조건표

| 경로 (Path) | 필터 조건 (Filter) | 수행 동작 (Action) |
| :--- | :--- | :--- |
| **오전 경로** | 응답 내용에 '오전' 포함 시 | 오전용 시트 기록 + 오전 안내 메일 발송 |
| **오후 경로** | 응답 내용에 '오후' 포함 시 | 오후용 시트 기록 + 오후 안내 메일 발송 |

### 3.3 단계별 입출력 데이터 예시 (Sample Record)

| 단계 | 입력(Input) 예시 | 출력(Output) 예시 |
| :--- | :--- | :--- |
| **구글 폼** | 이름: 김철수, 시간: 오전, 메일: a@test.com | (JSON 데이터 형태 전달) |
| **라우터** | "오전" 키워드 매칭 여부 확인 | Path A 활성화 (True) |
| **구글 시트** | 이름, 메일 정보 | '오전_신청자' 시트 5행에 추가 |
| **이메일** | 수신자: a@test.com | 제목: [오전] 신청 완료 안내 메일 발송 |

## 4. 운영 및 유지보수 전략 (평가항목 #4, #6, #13, #14 보완)

### 4.1 무중단 실행 및 모니터링
*   **실행 주기:** 15분 간격으로 트리거가 작동하도록 설정하여 서비스 연속성을 보장합니다.
*   **모니터링:** Make의 'History' 탭을 통해 성공/실패 로그를 실시간 모니터링하며, 실패 시 관리자에게 즉시 알림이 오도록 설정했습니다.
*   **재시도 전략:** 네트워크 오류 등으로 실패할 경우, 'Incomplete Executions'에 저장된 데이터를 3회 자동 재시도하도록 정책을 수립했습니다.

### 4.2 보안 및 확장성
*   **민감정보 보호:** API 토큰, 비밀번호 등 민감 정보는 환경 변수로 처리하였으며, 공유 문서에 노출되지 않음을 확인했습니다.
*   **모듈화 방안:** '이메일 발송' 기능을 서브플로우(Sub-flow)로 분리하여, 향후 다른 설문 자동화에서도 해당 모듈만 호출하여 재사용할 수 있도록 설계했습니다.

## 5. 결론 및 향후 발전 방향 (평가항목 #15 보완)

### 5.1 노코드 도구의 한계
*   대량의 데이터(수만 건 이상)를 한 번에 처리할 때 속도 저하가 발생하며, 복잡한 수학적 연산이나 커스텀 UI 구현에는 한계가 있습니다.

### 5.2 코딩 확장 아이디어
*   **Google Apps Script 활용:** 구글 시트 내에서 복잡한 데이터 가공이 필요한 경우, 자바스크립트 기반의 Apps Script를 작성하여 1차 가공 후 노코드 툴로 넘겨주는 방식으로 보완할 수 있습니다.
*   **Custom Webhook:** 노코드 툴에서 지원하지 않는 앱은 파이썬(Python)으로 간단한 API 서버를 구축하여 Webhook으로 연결하면 무한한 확장이 가능합니다.
